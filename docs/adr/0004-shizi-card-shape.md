# 识字卡片按已实现口径收口：一页两卡、部件拆解并入口诀、多音字卡一条一个读音

五期 DESIGN 原文写的是「学分两屏」和「田字格 + 部件拆解」，实现时做成了**一页两张卡**（① 田字格 + 区分口诀 ② 用一用）且**部件拆解并进口诀文案**。生产多音字篇时又发现「字族」在这张卡上根本不是「一组字」，而是**同一个字的多个读音**，于是 `chars` 在多音字篇一条一个读音、同一个字重复出现。三条都按已实现口径收回文档，不改代码。

## Considered Options

- **翻页**：改成严格两步翻页最贴 DESIGN 字面，但这一屏本来就不长，多一次点击对三年级孩子是纯成本；而且当前版本已经过像素验收（上一轮就是靠验收改掉了田字格虚线对比度、默认全文注音两处）。DESIGN 说的「两屏」用「一页两张卡」表达，屏数没变，只是不用手势翻。
- **部件拆解独立字段 + 独立组件**：拆开要多一个 schema 字段、一个渲染组件、一条校验规则，还要回改已交的 50 张卡。收益只是「和 DESIGN 字面一致」——口诀「已不封口，已半封口，巳全封口」本来就同时说了部件和区别，拆出来等于同一句话写两遍。
- **多音字卡另起一套 schema**（比如 `readings[]`）：语义上更干净，但要为 25 张卡新增一条渲染路径和一套字段校验。复用 `chars` 让 `titleOf` / `metaOf`、复习页、测验页零改动就能跑，代价是「同一个字会出现多次」这个约定要写进 STYLE-GUIDE，并且消费 `chars` 的视图得按字归并。
- **学习页把同一个字画成两格田字格**（每格一个读音）：这是复用 `chars` 后最省事的渲染，验收时否掉了——两格一模一样的字看着像渲染 bug，家长第一反应是「为什么分开写」，而田字格的任务是认字形，同一个字画两遍不增加任何信息。改成一格、读音并列在格子下面。

## Consequences

- 多音字卡的 `chars` 允许同一个 `zi` 重复，所以「族内字不重复」「`word` 是全体成员并列」「拼音必须带调」这三条形近字篇的规则对它不成立，改由 `server/shizi-rules.js` 按篇章分支校验；轻声（地 de、得 de）不带声调是合法的，读音以 pinyin-pro 的多音列表为准。
- 同一个字在一张卡上有多个读音，凡是把 `chars` 当「一组不同的字」来渲染的地方都会出错：`LearnView` 的田字格要按字归并（`ziCells`，读音并列）、按字钉的拼音表要改成按例句逐条钉（`fixesFor`，否则两读音互相覆盖）、`GroupView` 的缩略位要按字去重（不然显示成「长长」）、`v-for` 的 key 不能只用字。以后新增消费 `chars` 的视图都要记住这四条。
- DESIGN 里「田字格 + 部件拆解」的措辞已改写；术语表 `CONTEXT.md` 的「字族」本来就定义了「一个字的多个读音」这一形态，不需要新增术语。
- 这两处不是待办：如果日后要改成两步翻页或拆出部件字段，那是新的产品决定，要重开一轮，不要当成还债。
